First agency

Feel Think → Act → Observe on a real task: tools touch disk, you approve risk, a file receipt opens offline.

What “agency” means here

Chat is answers. Agency is action under your rules: the model Thinks, requests tools (Act); Hermes runs them; you approve what is dangerous; Observe feeds results back; you can open the result without trusting the chat alone.

Your messaging app (lesson 05) is a second window, not the proof. Prove hands on Desktop first, then optionally repeat a short check from your phone.

Chat onlyAgency (this lesson)
Text in, text outTools touch files / shell / browser
You copy-paste resultsA file on disk is the receipt
No risk gateApprovals stop reckless actions
No loop vocabularyYou can name Think → Act → Observe on your run
Love / Joule Work: cooperate with the human (approvals, honesty); spend energy only on useful work — not thrashing tools for show.

Think → Act → Observe on this mission

Before you start, expect this cycle at least once. You do not need to see secret “chain of thought” text — you need to recognize the steps.

  • ·If a tool errors, that error is still an observation — good agents re-plan; bad ones invent success
  • ·If you deny an approval, the observation is “denied” — the model should stop or ask, not sneak around
  • ·Write three short lines in the receipt after the run: Think (what it planned) · Act (tools you saw) · Observe (what came back)
StepOn today’s mission
ThinkModel plans: list folder → pick three largest → draft archive plan → write file
ActTool calls: list directory, write agency-receipt.md (maybe more). Approvals may fire
ObserveTool results return (file list, write ok/error). Model uses them for the next step or the final reply
Same as lexicon 01: the loop is agent/harness-level (LLM only does Think). Frameworks (smolagents, LangGraph, …) implement that loop differently; Hermes is *your* harness running it on *your* host.

Anatomy of a tool call (no code required)

A tool is not a vibe. It is a named action with arguments and a result. The model proposes the call; Hermes executes; the result becomes a message in the session.

  • ·Prefer small tool surfaces for this mission: file tools (+ shell only if needed)
  • ·Structured tools beat long improvised shell when both exist
  • ·A clear error is better than a silent wrong success

Mission of the Day (one story)

Pick a real folder you own (Downloads or a course notes folder). Goal: leave behind one markdown file you can open in any editor — not a clever chat monologue. Name your agent in the receipt if you like (e.g. “Run by: my-harness”) — optional personality, required file.

One-screen finish line: tools ran · you approved or denied once · agency-receipt.md opens offline with a short Think / Act / Observe note. File over chat.

Steps · tap the number to check0/4
  1. In Desktop chat, ask: “Look at [folder path I give you]. List the three largest items. Propose a simple archive plan. Write the plan to agency-receipt.md in [path I choose]. Do not delete anything. After tools finish, include a short Think/Act/Observe summary at the bottom of the file.”
  2. When tools ask for approval, read once. Approve only safe steps; deny anything that deletes or leaves the folder you named.
  3. Open agency-receipt.md yourself offline. If the file is missing, the mission failed — fix tools/path and retry.
  4. Optional pocket check: from your lesson-05 messaging app, ask “Summarize agency-receipt.md in three bullets” (only if gateway is up). Desktop proof still counts without this.

Proof 1 — hands (tools)

Open Tools ↗ / Dashboard for this profile. Keep the tool surface small: file + shell (or the minimum needed for the mission). Extra tools raise fixed cost and confusion — and give the model more Act options to thrash.

  • ·Prefer structured tools over long improvised shell when both exist.
  • ·A failing tool should return a clear error so the model can Observe and recover.
  • ·Scope tools to the job — this mission does not need every MCP server on earth.

Proof 2 — control (human in the loop)

Agency without a gate is a liability. Smart approvals ↗ may pass low-risk steps and stop on uncertainty. Manual is slower and fine. Full auto-approve modes (sometimes labeled YOLO) are expert-only — leave them off for this course.

Steps · tap the number to check0/3
  1. Confirm approval mode is smart or manual (not full auto-approve / YOLO).
  2. Force one decision: e.g. a write outside the allowed path should be denied, or a write inside should be approved on purpose.
  3. Write one line in agency-receipt.md: “Approval mode: … · I approved/denied: …”

Proof 3 — receipt (file over chat)

If you cannot open the result without Hermes, you do not own the outcome. The receipt file is the Part I finish line for agency.

  • ·Path is absolute and under a folder you control.
  • ·Content names the three largest items + plan (even if rough).
  • ·You opened it in a normal editor, not only in chat.

Know your cost (light)

Provider ↗ (OpenRouter, OpenCode, …) is where the key lives; model is capability and price. Free tiers still have limits. Before blaming the model, know what is already loaded in an empty session.

Steps · tap the number to check0/2
  1. Note which provider + model handled the mission (one line in the receipt).
  2. Optional: open the context / usage view in Desktop and jot the two biggest slices (tools / skills / memory).

MCP — only if you need a service

MCP ↗ plugs external services (docs, drives, repos). Skip MCP for the Mission of the Day unless a service is required. Each server is new trust surface.

  • ·Add one server for a concrete need — not a catalog “for later.”
  • ·Prefer OAuth over long-lived tokens when available.
  • ·Secrets stay out of chat.

Other ways to deploy

▸Tool backends and host isolation

Shell tools use a terminal backend. On a dedicated host you may run tools more freely. On a personal machine, Docker ↗ (or a VPS) is the responsible default — not “later if you feel like it.”

  • ·Dedicated host process — ok when the box is lab-only
  • ·Docker backend — commands isolated from the host OS (required compromise on a daily-driver)
  • ·SSH / VPS / cloud sandboxes — tools run on another machine you can wipe
  • ·Own infra vs cloud API models — brain location is independent of tool backend; cloud brains still send chat content off-box
  • ·Multi-machine ops — Desktop here, workers or gateway on a VPS
For production isolation, team shared hosts, or compliance constraints, contact Delta V — tailored Hermes deployments by our engineers.
