Part II · Compounding harness · 11

Cron runbooks

Automation that is a full runbook — not a one-line hope. Each fire is amnesia.

25 min

Amnesia is a feature

Cron usually lives with the always-on gateway. Each run is a fresh, isolated session that knows nothing about “that issue from yesterday.” Write a self-contained runbook in the job prompt.

  • ·Include host/path/command/expected state/delivery target/success and failure behavior.
  • ·silent: suppress “all good” noise; still surface failures.
  • ·no_agent / script-only path: when a deterministic check needs no model tokens.
  • ·Wake gate: cheap pre-check first; wake the model only when something changed.
  • ·Jobs should not spawn infinite new jobs — runaway self-scheduling is blocked in healthy setups.
  • ·Dangerous commands in cron: prefer approvals.cron_mode deny (default) so headless jobs cannot YOLO host damage.

Build one job

  1. 01Define a tiny job: e.g. weekday 08:00 — three AI headlines, short summary, deliver to Telegram (or a local file if no gateway).
  2. 02Write the prompt as if the agent has amnesia (full runbook). Save as cron-runbook.md.
  3. 03Create it in Desktop cron UI or Hermes cron flow for your version.
  4. 04Run once manually if possible, then leave it scheduled — or stop after dry-run if you are offline.
Spend on cron is easy to waste. Prefer script checks first; wake the model only when the check fails or changes.
