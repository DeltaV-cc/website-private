Part I · Sovereign agent · 06

First agency

You already have the pocket. Now tools, spend control, and a Desktop quick win.

30 min

Type 1 — agent with tools

You already talk to Hermes from Telegram (previous module). Now open its hands: terminal, browser, filesystem, search (when configured). The model requests; Hermes executes.

In Desktop: open Tools / Dashboard, confirm toolsets for this profile, run the proof from Desktop chat (Telegram is fine as a second surface).

  • ·Prefer structured tools over long shell improvisation when both exist.
  • ·A failing tool should return a clean error so the model can recover.
  • ·Scope tools to the job. Research does not need full write+shell if read+web is enough.
  • ·If Portal setup enabled Tool Gateway tools, verify them in the Tools UI.
  • ·Sessions can resume — continue a known thread for long jobs when the UI offers it.
  • Tools ↗
  • Sessions ↗

Terminal backend (Advanced — relevant when tools hit the shell)

When tools run shell/file work, Hermes uses a terminal backend. Day one stays local (host process). In Desktop Settings → Advanced you will often see Docker (and other backends): commands run in a container so mistakes are less likely to wreck the host.

  • ·Local (default for this course) — simplest; approvals still matter
  • ·Docker — isolation; enable only after chat + tools work and you understand the trade-off
  • ·SSH / cloud sandboxes — remote workers; same idea as “brain local, hands elsewhere”
Do not flip Advanced → Docker mid-proof just to experiment. Know the setting; harden after Part I if you want.
  • Docker / backends ↗
  • Security (containers) ↗

MCP — plug services carefully

MCP connects external services (docs, drives, repos, APIs) through a standard interface. Treat every MCP server as new code on the agent’s trust surface.

  • ·Add one server for a real need — not every server you can find.
  • ·Filter tools to the smallest useful surface.
  • ·Prefer OAuth over long-lived tokens when the server offers it.
  • ·Secrets should not appear in chat; store them in .env / setup.
  • MCP with Hermes ↗
  • Tools docs ↗

Spend intelligence wisely

Provider and model are different decisions. Provider = auth and billing. Model = capability and price. Use a strong model where mistakes are expensive; cheap models for auxiliary jobs (titles, search helpers, compression) when your setup supports them.

  • ·Stabilize one primary model before adding fallbacks.
  • ·Credential pools (multiple keys) help survive rate limits — not only multi-billing.
  • ·Local models: set a large enough context window; broken tool loops are often truncated context, not “Hermes is dumb.”
  • ·Providers screen is also where remote/local OpenAI-compatible endpoints show up (including a model host that is not this PC).
  • ·If you run a local OpenAI-compatible endpoint later, keep real OAuth credentials out of third-party tools.
  • Configuration / providers ↗

Proof task

  1. 01Ask: “List the largest folders in my Downloads (or home), propose an archive plan, write the plan to a markdown file in a safe path I choose.”
  2. 02Approve tool actions if prompted. Prefer smart approvals: safe actions pass, dangerous ones ask.
  3. 03Open the markdown file yourself. That file is the receipt.

Desktop cockpit (expected on the default path)

If you followed module 03’s default path, Hermes Desktop is your everyday cockpit for tools, approvals, and sessions for the rest of the course — not an optional extra.

Stretch proof (recommended): ask the agent to create a small custom UI widget (e.g. system memory monitor) if your build supports it. If it can change the Desktop, you felt agency twice — phone + machine.

Keep Desktop open as the home surface for the rest of the course.

Human in the loop (type 6)

Default safety: dangerous actions need approval. Smart mode lets an auxiliary judgment pass low-risk actions and escalate uncertainty. Keep this on. Mistakes on email, deletes, and deploys are expensive. YOLO-style modes exist for experts; they are not the course default. Even with YOLO, a hardline blocklist still refuses catastrophic host wipes — do not treat YOLO as “safe.”
