Part II · Compounding harness · 09

Skills

Procedural memory that loads on demand — not a second system prompt dump.

20 min

What a skill is

A skill is a reusable instruction package (SKILL.md). Front matter names and describes it; the body teaches the procedure. Hermes sees names + descriptions first — a vague description means the right skill may never load.

Skills are progressive disclosure: the catalog stays cheap; only the selected skill body enters the prompt. That is how you keep a large library without burning the context window every turn.

  • ·Skill = procedure / knowledge package (agentskills-compatible).
  • ·Plugin / MCP = executable surface or product hooks — different layer.
  • ·Slash commands (e.g. /plan) and /learn can capture workflows as skills when your build supports them.
  • ·Install narrowly; let security scans run on hub skills before you trust them.
  • ·Pin / curator: business-critical skills should not vanish to automated cleanup — see Curator docs when you outgrow defaults.

Desktop first

  1. 01Open Skills in Hermes Desktop.
  2. 02Paste the list into skills-notes.md under your course notes folder.
  3. 03Try one bundled skill appropriate to your OS (e.g. a file or shell helper).
  4. 04Optional: browse hub and install one official skill after reading the scan warning — log why you installed it. Do not install a catalog “for later.”
If everything is “on,” the model spends tokens deciding which skill, not doing the job. Least privilege on skills. Skills Hub is a map — not homework.
